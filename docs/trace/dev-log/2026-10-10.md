**配置驱动的通用 harness 接入** ✅（核心能力，见 docs/02-tech/harness-registry.md）：
- `config/harnesses.json` 定义任意 harness：内置协议（protocol）/ 任意 ACP（command+args）/ MCP 工具集（mcp，P1）。
- 领域路由按 domains 自动生成；本地实验（pi/opencode）验证通过。
- 43 测试全绿（含 harness-registry 7 个新测试）。

**Hermes 定性最终修正**（ADR-0007 supersede ADR-0006，恢复 ADR-0004）：Hermes = NousResearch 的 hermes-agent（ACP harness，远端阿里云/腾讯云），财经能力（hermes-investment 的 MCP）是 Hermes Agent **自带的工具**。接入走通用 `command+args` 的 SSH 隧道：`command:"ssh", args:["<host>","hermes","acp","--accept-hooks"]`。三轮反复（ACP → MCP → ACP）最终回到 ADR-0004 的 SSH 方案。

**协调模型设计**（docs/02-tech/coordination-model.md）：前台豆包作「总指挥」，多专家自动协调、自动判断、自动继续，关键决策点才问用户；专家间互相委派用总指挥居中替代（Pi 不支持 third-layer delegation）。

**总指挥提示词已实现**（2026-10-12）：`config.mjs` 的 `buildSpawnThinkingDescription` 从 harnesses.json 动态生成专家列表 + 注入「自动协调」语义，经 `createGatewayApplication({ spawnThinkingDescription })` 替换前台 spawn_thinking 工具的 description。44 测试全绿。待真实对话验证前台是否按“总指挥”语义多轮协调。
